# Handoff: bench harness for partial hardware (LOC-25), 2026-10-27 05:12

Local only. Nothing was pushed to GitHub, and the cloned team repos were not modified.

## Request

The user asked: "Can you make this testable even without most components? (i.e. everything but the camera is
connected)". When asked which hardware would be connected, they answered "Any mix (both)". So each input can be
real, recorded or simulated independently, and one harness covers all the combinations.

## What exists now

New package `localization_work/td_bench/` (ament_python layout, CLI `python -m td_bench`, console script
`loc_bench`):

| File | Contents |
|---|---|
| `sources.py` | `World` (shared ground truth for simulated parts) and the input sources:<br>odometry: `SimOdometry`, `StationaryOdometry`, `LiveOdometry.push()`<br>head: `SimHead`, `FixedHead`, `LiveHead.push()`<br>camera: `SimCamera`<br>game: `ScriptedGame`, `UdpGame`<br>ball: `SimBall`<br>team: `SimTeam`, `UdpTeam`, `NoTeam`<br>`default_world(walk / tripod / still)` |
| `vision.py` | `render_field_image`; line-pixel detector (white next to grass, horizon cut); `image_observations` (back-projection with the believed head angles); `ImageCamera`. Frame sources: `SyntheticFrames`, `FolderFrames` (.npy, or .png/.jpg with Pillow), `RealSenseFrames` (projector forced off; **untested**, no D435 here). `D435_HALF` intrinsics. |
| `record.py` | `Recorder` → `.npz` (no pickle). `Recording`, plus `ReplayCamera`, `ReplayOdometry`, `ReplayHead` and `ReplayGame`. Replay is bit-exact. |
| `bench.py` | `Bench(...).run(duration, realtime=)` → `BenchResult.report(out)`. The tick order matches the planned LOC-20 node: events → predict → update → side → ball → team. Ground truth can be a World, a Recording, a fixed pose, or None. |
| `__main__.py` | CLI flags `--camera`, `--odom`, `--head`, `--game`, `--team`, `--ball`, `--truth`, `--world`, `--start`, `--start-pose`, `--record`, `--realtime` and others; examples are in the module docstring and the README |

Shared change in `td_field_model/sim.py`: projection, back-projection and floor covariances moved into
module-level functions (`project_floor`, `backproject_pixels`, `floor_covariances`). The `Simulator` methods
delegate to them, and behaviour is unchanged (78 tests pass).

## Verified

`td_bench` has 25 tests:
- **Sources:** every source on its own.
- **Vision:** detected points lie on the lines (median under 5 cm), no false points on plain grass or white walls,
  and a 6° pitch error measurably pushes the points off the lines.
- **Mixes:**
  - All simulated: search from the own half converges to under 0.3 m.
  - Camera only (synthetic images, stationary odometry, fixed head): a start 40 cm / 6° off is corrected to under
    0.2 m and 5°.
  - Everything but the camera, in real time: odometry is pushed from a producer thread; a GameController and a
    teammate run over real UDP sockets on loopback.
  - Scripted penalty: the filter pauses and is re-seeded.
  - Simulated ball and team.
- **Record and replay:** replay matches the original run exactly.
- **CLI:** smoke tests, including replay and a run without ground truth.

Lint: ruff check and format are clean on all four packages.

## Known limits / next steps

- The image detector is a bench stand-in. LOC-17 (the real field-feature detector) is still open, and its output
  should plug into `ImageCamera` in its place (it should return the same `Observations`).
- `RealSenseFrames` has never run against a D435. The first person with the camera should run:
  `python -m td_bench --camera realsense --odom stationary --head fixed:0,PITCH --world still --start known
  --start-pose X,Y,TH --truth known:X,Y,TH --mount-height H --realtime --duration 60 --record runs/x.npz --out reports/x`
  and check `bench_log.txt` and `report.md`.
- `UdpGame` / `UdpTeam` have only been tested on loopback, never against the official GameController or the field
  network.
- There are no ROS bindings. `LiveOdometry` and `LiveHead` are the hook for a ROS callback until LOC-20 exists.
- New tracker row: LOC-25 in `docs/localization_implementation_plan.md` §6. The README has a "Bench testing with
  partial hardware" section.
